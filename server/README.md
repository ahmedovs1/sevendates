# Mailer — серверная отправка заявок

Маленький Node-сервис: принимает заявку с формы по HTTP и отправляет письмо
через SMTP `mail.sevendates.uz`.

Он нужен потому, что **браузер не умеет SMTP** — это TCP-протокол, из страницы
доступен только HTTP. И потому, что пароль от почты нельзя класть во фронтенд:
всё, что Vite видит как `VITE_*`, попадает в публичный JS-бандл и читается любым
посетителем через DevTools.

## Установка на VPS

```bash
cd /var/www/sevendates/server
npm ci --omit=dev
cp .env.example .env
nano .env            # вписать SMTP_PASS и MAIL_TO
chmod 600 .env       # пароль не должен читаться другими пользователями
npm run verify       # проверка подключения к SMTP, письмо не отправляется
```

Скрипты сами подхватывают `.env` из своей папки, поэтому работает и
`node verify-smtp.js`, и `node index.js` — без флагов.

`npm run verify` отвечает `OK — authenticated as ...` — значит хост, порт, логин
и пароль верны. Это отделяет «неправильные настройки» от «письмо не дошло».

## Запуск через systemd

`/etc/systemd/system/sevendates-mailer.service`:

```ini
[Unit]
Description=Seven Dates callback mailer
After=network.target

[Service]
Type=simple
User=www-data
WorkingDirectory=/var/www/sevendates/server
EnvironmentFile=/var/www/sevendates/server/.env
ExecStart=/usr/bin/node index.js
Restart=on-failure
RestartSec=5

[Install]
WantedBy=multi-user.target
```

`EnvironmentFile` подставляет переменные сам, поэтому `--env-file` здесь не
нужен — запускается напрямую `node index.js`.

```bash
systemctl daemon-reload
systemctl enable --now sevendates-mailer
systemctl status sevendates-mailer
```

## nginx

Сервис слушает только localhost:8787. Важное отличие от обычной SPA-раздачи:
**HTML должен проходить через Node**, иначе не подставятся SEO-теги. Файлы
(js, css, картинки) nginx по-прежнему отдаёт напрямую — быстро и мимо Node.

```nginx
server {
    server_name sevendates.uz;

    root /var/www/sevendates/dist;

    # Есть такой файл — отдаём сразу. Нет — это маршрут SPA, идём в Node.
    location / {
        try_files $uri @spa;
    }

    location @spa {
        proxy_pass http://127.0.0.1:8787;
        include proxy_params;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }

    # API формы и админки
    location /api/ {
        proxy_pass http://127.0.0.1:8787;
        include proxy_params;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }

    # Картинки, загруженные через админку. Лежат вне dist/, чтобы сборка их не стирала.
    location /uploads/ {
        proxy_pass http://127.0.0.1:8787;
        include proxy_params;
    }
}
```

`X-Forwarded-For` обязателен: по нему работает ограничение частоты запросов.
Без него все заявки и попытки входа будут выглядеть как с одного адреса.

Если в вашей сборке nginx нет файла `proxy_params`, замените `include` на
`proxy_set_header Host $host;` и `proxy_set_header X-Real-IP $remote_addr;`.

## Проверка

```bash
curl http://127.0.0.1:8787/api/health
# {"ok":true}

# пустые поля — должно быть 400 и никакого письма
curl -X POST http://127.0.0.1:8787/api/send \
  -H 'Content-Type: application/json' -d '{"name":"","phone":"","email":"x"}'
```

## Что делает сервис

- **Ограничение частоты** — 5 заявок за 10 минут с одного адреса. Публичный
  эндпоинт, который шлёт почту, без этого превращается в открытый релей: одним
  скриптом можно испортить репутацию ящика и загнать домен в чёрные списки.
- **Проверка полей** — имя, телефон и корректный e-mail обязательны, длина
  ограничена, тело письма обрезается до 4000 символов.
- **Защита от инъекции заголовков** — переносы строк в полях схлопываются в
  пробел, иначе через поле «имя» можно было бы дописать `Bcc:` и рассылать спам.
- **Reply-To на посетителя** — отвечать на заявку можно прямо из почты.
- Ошибки SMTP пишутся в журнал сервиса, наружу отдаётся только `502` без
  подробностей о почтовой инфраструктуре.

## Смена пароля

Пароль задаётся только в `server/.env`. Файл в git не попадает (правило `.env`
в корневом `.gitignore`). После смены — `systemctl restart sevendates-mailer`.

## Админка

Открывается по адресу `/admin`, вход по паролю из `ADMIN_PASSWORD`.

Что редактируется:

- **SEO** — title, description и картинка превью для каждой страницы и языка.
  Пустое поле означает «взять заготовленный текст», он показан подсказкой.
- **Контакты** — юрлица, телефоны, адреса и почта офисов, ссылки на соцсети.
  Меняется сразу и на странице «Контакты», и в футере.
- **Тексты** — любая строка сайта на трёх языках, с поиском по ключу.
- **Списки** — события, коктейли, моктейли и награды, с заменой картинок.

### Как это устроено

Админка сохраняет **только отличия** от контента, зашитого в сборку. Пустое
поле — это не пустая строка на сайте, а «вернуть исходное значение». Отсюда два
следствия:

- испортить сайт правкой нельзя: очистка поля возвращает исходный текст;
- если сервис недоступен, сайт продолжает работать на зашитом контенте, а не
  показывает пустые страницы.

Файл с правками — `server/data/overrides.json`. Запись атомарная (через
временный файл и переименование), так что сбой посреди сохранения не оставит
половину JSON. Файл стоит включить в резервное копирование: сборка его не
восстановит.

Загруженные картинки лежат в `server/uploads/` — намеренно вне `dist/`, который
стирается при каждой сборке.

### Доступы

Вход по логину и паролю. В разделе «Доступы» можно открыть доступ новому
человеку, забрать его и сменить собственный пароль. Учётные записи равноправны:
ролей нет, все редактируют всё.

Ограничения, заложенные намеренно:

- нельзя удалить собственную учётную запись и нельзя удалить последнюю —
  иначе в админку было бы не попасть;
- пароль не короче 8 символов, логин — латиница, цифры, точка, дефис,
  подчёркивание;
- посмотреть чужой пароль нельзя, можно только задать новый.

Пароли хранятся в `data/users.json` хешами scrypt с индивидуальной солью:
украденная копия файла не выдаёт сами пароли. Файл включите в резервное
копирование вместе с `overrides.json`.

**Первый вход.** Пока в `data/users.json` нет ни одной записи, сервис создаёт её
при старте из `ADMIN_USERNAME` и `ADMIN_PASSWORD`. После этого переменные не
используются — их можно очистить.

`SESSION_SECRET` — ключ подписи cookie сессии, любая длинная случайная строка:
`openssl rand -hex 32`. Если не задать, сервис сгенерирует случайный при старте
и предупредит в журнале: сайт будет работать, но редактора будет разлогинивать
при каждом перезапуске.

Сессия живёт 12 часов, cookie помечена `HttpOnly` и `SameSite=Strict`, так что
из JavaScript она недоступна. Попытки входа ограничены 10 в 10 минут с адреса —
счётчик в памяти, перезапуск сервиса его сбрасывает.
